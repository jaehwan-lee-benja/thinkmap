통합 세션의 **"랩업 회고"**를 수행한다. 한 묶음의 병렬 작업(worktree들)이 착지한 시점을 돌아보고, 개발일지에 일기 형태로 기록한다. (회고는 대화 맥락이 필요하므로 서브에이전트가 아니라 메인 세션인 네가 직접 쓴다.)

## 절차

### 1. 범위 확정 (지난 회고 이후)
- `docs/DEVLOG.md` 의 가장 최근 엔트리 날짜를 확인해 "그 이후"를 이번 범위로 잡는다. (파일이 없으면 최근 작업 묶음 전체.)
- 사실 수집(추측 말고 실제 상태):
  - `git log --oneline --merges` — 이번에 머지된 세션들
  - 적용된 프로덕션 마이그(있으면 무엇), Edge 재배포 여부
  - `gh run list --limit N` 로 배포 성공 여부
  - 현재 `git worktree list` — 은퇴한 것/남은 것, 마감·보류된 세션
- 대화 맥락에서 **"왜"와 곁가지 배움/사고(hazard)**를 보탠다(이건 너만 안다).

### 2. 회고 엔트리 작성 (일기체, 한글)
날짜 헤더 + 아래 뼈대:
- **이번 판의 방식** — 오케스트레이션 형태(worktree-per-session 등)
- **배포 완료** — 세션별 1~2줄: 무엇을 왜 고쳤나
- **마감/보류** — 접은 것, parked 된 것(재개 포인트 명시)
- **곁가지에서 배운 것** — 운영 개선·재발방지·마이그 규율
- **남은 확인거리** — 실사용 점검 대기 항목
사실 위주지만 회고답게. 과장·홍보 금지(DESIGN-PHILOSOPHY 정신).

### 3. 저장
- `docs/DEVLOG.md` **최상단(헤더 아래)에 새 엔트리를 prepend**(최신이 위). 파일 없으면 생성.
- 같은 내용을 공용 복붙 메모장(`~/claude-project/.worker-launch/복붙용_임시메모장.txt`)에도 써서 사용자가 개인 일기에 복사할 수 있게 한다.
- docs 커밋(앱 변화 없음 = 배포 불필요, 다음 앱 배포 때 함께 올라감). thinkmap repo 에 커밋.

### 4. 마무리
무엇을 기록했는지 한눈에 보고. 이어서 `/기억정리` 를 돌릴지 사용자에게 물어본다(선택).

## 랩업 경계 (자동 권유 기준)
**랩업 = 활성 worktree 0개(통합 홈만) + main==origin + working tree clean.** 이 상태면 한 묶음이 착지한 것. 통합 세션은 이 경계가 감지되면(마지막 worktree 은퇴·배포 직후 등) 사용자에게 **"/회고 실행할까요?"** 를 먼저 권한다. 사용자가 명시 호출해도 된다.
