## 1. 배경 & 목표

- 매월 직원 근태 기록(이카운트/출입통제기 로그)을 받아 **수기로 급여를 계산**하고 있다.
  기록이 지저분(중복 출근, 라벨 오류, 퇴근 누락)해 계산이 번거롭고 실수가 잦다.
- **목표**: 근태 원본을 업로드하면 인원별 **기본 급여명세서**가 자동 생성되고,
  관리자가 시급·시간·수당/공제를 **세부 조정**해 최종 명세서를 확정·보관할 수 있다.
- **성공 기준**:
  - 업로드 1회로 전 직원 기본 급여가 즉시 산출된다.
  - 기록 이상치(퇴근 누락 등)가 명확히 표시되어 누락 없이 보정된다.
  - 인원별 시급 차등(평일/주말, 개인별)이 손쉽게 반영된다.

## 2. 범위 / 비범위

**범위 (이번 작업)**
- 4월 근태 형식 기준 업로드 → 파싱 → 인원별 일자별 근무시간 산출
- 평일/주말 시급 + 인원별 시급 재정의 기반 기본 급여 계산
- 인원별 급여명세서 화면 + 행 단위 세부 조정(시급/시간/수당/공제)
- 마스터 전용 접근, 사이드바에서 마케팅 캔버스 아래 배치

**비범위 (이번 작업 제외)**
- 4대보험/소득세 자동 공제 계산 (5인 미만 + 단순 시급제 가정, 수동 입력으로 대체)
- 주휴수당·연장/야간 가산 자동화 (옵션 훅만 두고 기본 미적용)
- PDF/인쇄 양식, 이메일 발송, 급여 이체 연동 (후속 단계 후보)
- 근태 기기 직접 연동 (수동 업로드만)

## 3. 사용자 & 권한

> payroll 의 `is_master()` 단일 게이트는 ThinkMap 권한 **패러다임 C(마스터 전용)의 기원**
> 이며, 이후 goals/dashboard 가 이 패턴을 재사용했다. 전체 권한 지도는
> [ACCESS-MODEL.md](./ACCESS-MODEL.md) 참조.

- **마스터(`app_users.role = 'master'`) 전용.** 일반 사용자/뷰어에게는 메뉴·페이지·데이터가
  전혀 노출되지 않는다.
- 이참에 **마케팅 캔버스(page_type frame/engine)도 마스터 전용**으로 전환한다.
  - 사이드바 "+ 마케팅 캔버스" 버튼: 마스터에게만 표시
  - 페이지 트리: 비마스터에게 frame/engine/payroll 페이지 숨김
  - 직접 URL/탭 접근 시에도 비마스터는 접근 거부
- 임퍼소네이션/뷰어 모드에서는 급여 데이터가 보이지 않아야 한다(실제 세션 기준 마스터만).

## 4. 용어 정의

| 용어 | 정의 |
| --- | --- |
| 스캔(scan) | 출입통제기에 1회 찍힌 기록 (출근/퇴근/출입 라벨 무관) |
| 세션(session) | 한 직원의 하루치 근무 = 그 날 첫 스캔 ~ 마지막 스캔 |
| 평일/주말 | 토·일을 주말로 분류 (공휴일은 이번 범위 밖, 수동 보정) |
| 이상치(anomaly) | 스캔 1회뿐 등 근무시간을 신뢰할 수 없는 세션 |
| override | 전역 시급 대신 개인별로 책정한 시급 |

## 5. 데이터 모델

급여명세서는 (a) 인원별 시급·표준시간 설정, (b) 월별 명세서(지급/공제 항목 + 조정값),
(c) 근태 원본 스냅샷을 가진다. **결정: 전용 테이블** (급여는 마스터 전용 민감 데이터 +
월별 이력 필요 → schedule_events/daily_blocks 선례와 동일하게 전용 테이블 + RLS 마스터 전용).
`pages.content_tiptap` 에 욱여넣지 않는다.

- `pages` 테이블에 `page_type = 'payroll'` 추가 (schedule 선례 동일,
  `migrate-pages-allow-payroll.sql`). 급여 진입점 페이지 1개.
- `payroll_sheets` (월별 1행): `{ id, page_id, pay_month '2026-04', data jsonb, updated_at }`.
  `data` = `{ config(전역 시급·표준시간·고용보험요율), overrides(인원별), rows(인원별 명세서 전체) }`.
  RLS: `is_master()` 만 select/insert/update/delete.
- 인원별 시급 등 "설정"은 매월 재사용되므로 `data.config`/`data.overrides`에 저장하고,
  새 달 생성 시 직전 달 설정을 복사해 초기화.

## 6. 근태 파싱 규칙

> 구현·검증 완료: `src/utils/payroll/attendanceParser.js`

원본 형식은 신뢰할 수 없으므로 **라벨(01출근/02퇴근/00출입)에 의존하지 않는다.**

1. **입력 형식**: CSV / TSV / 엑셀 붙여넣기(탭) / 마크다운 표 모두 허용. 헤더 별칭으로
   컬럼 자동 매핑(발생일자/사용자명/발생시각/상태).
2. **날짜 forward-fill**: 발생일자가 첫 행에만 있고 이어지는 행은 비어 있음(병합 셀)
   → 직전 날짜로 채운다.
3. **세션 산출**: (직원, 날짜)별로 묶어 **첫 스캔 = 출근, 마지막 스캔 = 퇴근**.
   중복 출근(예: 9:48·11:36·11:37)이나 라벨 뒤바뀜(퇴근 9:33 → 출근 9:34)은 자동 흡수.
4. **이상치**: 스캔이 1회뿐이면 `anomaly: 'single-scan'`, 근무 0분 + 경고.
5. **주말 분류**: 토·일은 UTC 기준 요일로 판정(로컬 타임존 영향 제거).
6. **출력**: `sessions[]`(직원·일자·근무분·주말여부·이상치), `employees[]`,
   `dateRange`, `warnings[]`.

## 7. 급여 계산 규칙

> 구현·검증 완료: `src/utils/payroll/payrollCalc.js` — **실제 발송된 4월 PDF 숫자로 검증**.

핵심 모델(현장 실무 = 표준시간제):
- **기본급 = 시급 × 표준 7시간 × 근무일수.** 주말 근무일은 주말 시급으로 별도 집계.
  실제 근태 분이 아니라 **표준 7시간/일**을 쓴다(정민들레만 6.5h). 실제 근태시간은
  참고·보정용으로 함께 보여준다.
  - 검증: 김향숙 일요일 3일 × 7h × 12,500 = **262,500** (실제 PDF 일치)
  - 조우영 10,500×7×8 = 588,000 / 배미진 13,000×7×3 = 273,000 (일치)
- **기본 시급**: 평일 10,500 / 주말 12,500. **인원별 override는 평일·주말 각각** 지정 가능
  (예: 배미진은 주말도 개인요율 13,000). 표준시간도 인원별 override 가능.
- **고용보험 = 급여계 × 0.9% 자동**(편집 가능). 소득세/지방소득세/국민연금/건강보험은
  5인 미만이라 기본 0(수기 입력). 안선영 1,025,650×0.9%≈9,170 / 김도윤 812,500×0.9%≈7,260.
- **지급항목**: 기본급(자동) + 연장수당·주휴수당·보너스·인센티브·교통비·식대(수기 조정).
- **급여계 = Σ지급, 차감수령액 = 급여계 − 공제합계.** `recomputePayslip()` 으로 편집 시 즉시 재계산.

## 8. 화면 흐름 & 기능 요구사항

> 실제 발송 양식 확인 완료 (사르르목장 PDF). **두 템플릿** 존재:
> - **간이형(사르르목장)** — 시급/파트타임 직원 다수. 본 작업의 기본 명세서 양식.
>   `2026년 N월 급여명세서 / 성명·직책 / [지급항목·지급액 | 공제항목·공제액] /
>    공제합계 / 급여계 / 차감수령액 / "귀하의 노고에 감사드립니다. 사르르목장"`
> - **정식형(근로기준법)** — 정규직·대표. 4대보험+장기요양+산출식. **후속 단계**(수기/별 템플릿).

기능 요구사항:
1. **업로드**: 파일 업로드 또는 붙여넣기 → 즉시 파싱, 인식 직원 수·기간·경고 요약.
2. **인원별 기본 명세 자동 생성**: 기본급(=시급×7h×일수) 자동 채움 + 빈 조정 항목.
3. **세부 조정(행 단위)**: 시급(평일/주말)·표준시간 개별 수정, 지급/공제 항목 입력,
   조정 시 급여계·차감수령액·총계 실시간 반영.
4. **이상치 강조**: 퇴근 누락 등 보정 전까지 경고 유지.
5. **저장/불러오기**: 월별 명세 저장(`payroll_sheets`), 재진입 시 유지, 새 달은 직전 설정 복사.
6. (후속) 간이형 명세서 인쇄/PDF 출력 + 정식형 템플릿.

## 9. 엣지 케이스 & 정책

| 케이스 | 처리 |
| --- | --- |
| 퇴근 미스캔(스캔 1회) | 0분 + 이상치 표시. 정책: **수동 입력 보정**(기본). ※ 12장 확인 |
| 중복 출근/퇴근 | 첫·마지막 스캔으로 자동 흡수 |
| 출근/퇴근 라벨 뒤바뀜 | 순서 기준이라 영향 없음 |
| 자정 넘긴 근무 | 이번 범위 밖(주간 근무 가정). 발견 시 수동 보정 + 후속 과제 |
| 공휴일 | 평일로 계산됨 → 필요 시 수동으로 주말 시급/별도 처리 |
| 동명이인 | 현재 이름 기준 그룹핑. 발생 시 식별자 컬럼 도입 검토 |
| 휴게시간 | 기본 미적용. 적용 시 `breakRule` 옵션 (12장 확인) |

## 10. 사이드바 / 라우팅 통합

> 코드 위치 상세는 `PLAN-payroll-page.md` 참조.

- `isMaster` 를 `paneData` 컨텍스트에 노출 → Sidebar에서 사용.
- 사이드바: "+ 마케팅 캔버스" 버튼을 마스터 전용으로 게이팅하고, **바로 아래** "급여명세서"
  버튼 추가(마스터 전용). 클릭 시 payroll 페이지 find-or-create.
- 페이지 트리(`usePages`): 비마스터에게 frame/engine/payroll 숨김.
- 라우팅(`App.jsx`): `page_type === 'payroll'` → `<PayrollPage>`. 비마스터 접근 거부.

## 11. 단계별 로드맵

- **Phase 0 — 밑작업 (완료)**: 근태 파서 + 급여 계산 로직(명세서 모델) + 테스트. 실제 PDF 검증.
- **Phase 1 — 권한/메뉴/DB**: 마스터 게이팅(마케팅 캔버스 포함) + 사이드바 버튼 +
  payroll 라우팅 + `migrate-pages-allow-payroll.sql` + `payroll_sheets` 테이블.
- **Phase 2 — 화면(MVP)**: 업로드 → 인원별 기본 명세 자동 생성/표시 + 인원별 시급 설정.
- **Phase 3 — 세부 조정/저장**: 지급·공제 항목 편집 + 실시간 합계 + `payroll_sheets` 저장/불러오기.
- **Phase 4 — 운영 편의**: 월별 이력, 간이형 인쇄/PDF, 정식형(근로기준법) 템플릿.

## 12. 결정됨 / 확인 필요

**결정됨 (실제 양식·PDF 확인 후)**
- 양식 = **간이형(사르르목장)** 기본, 정식형은 후속.
- 근무시간 = **표준 7시간 × 근무일수** (실제 근태분은 참고·보정용 병기).
- 저장 = **전용 테이블 `payroll_sheets`**(월별), 새 달은 직전 설정 복사.
- 공제 = **고용보험 0.9% 자동**, 나머지 수기.
- 인원별 시급 override = **평일·주말 각각** + 표준시간.

**확인 필요 (진행하며 합의)**
- [ ] 퇴근 누락(단일 스캔)일의 근무일수 산입 여부 — 현재 "1일로 산입 + 경고", 시간은 표준 7h 가정.
- [ ] 보너스 산정 규칙 자동화 여부(현재 100% 수기. 일부는 기본급의 0.1~0.2 패턴이나 불규칙).
- [ ] 주휴수당 자동 판정(주 15h↑) 여부.
- [ ] 대상 월: 4월 근태로 4월 급여 생성(양식은 구조 참고).
