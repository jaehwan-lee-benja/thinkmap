## 1. 핵심 원칙

ThinkMap의 모든 최상위 블록은 토글이다. 토글이 이 에디터의 기본 단위다.

---

## 2. 노드 스키마 정의

```
name: 'toggle'
group: 'block'
content: '(paragraph | toggle)+'
defining: false
priority: 200
```

| 속성 | 값 | 의도 |
|------|-----|------|
| `content` | `(paragraph \| toggle)+` | 토글 안에는 paragraph와 하위 토글만 허용. **리스트(bulletList, orderedList, listItem) 불가** |
| `defining` | `false` | ProseMirror fitting 알고리즘이 붙여넣기 시 콘텐츠를 토글 내부로 밀어넣는 것을 방지. Enter/Backspace 등은 모두 커스텀 핸들러로 제어하므로 불필요 |
| `priority` | `200` | 다른 키보드 핸들러보다 먼저 실행 |

---

## 3. 토글 속성(Attributes) 목록

| 속성 | 타입 | 기본값 | 용도 |
|------|------|--------|------|
| `isOpen` | boolean | `true` | 하위 토글 표시/숨김 |
| `autoGenerated` | boolean | `false` | 토글 열 때 자동 생성된 빈 토글 표시 (닫을 때 자동 삭제) |
| `isTodo` | boolean | `false` | 체크박스 UI 활성화 |
| `todoChecked` | boolean | `false` | 체크 상태 |
| `todoStatus` | string\|null | `null` | `"hold"` (보류) 또는 `"progress"` (진행중) |
| `backgroundColor` | string\|null | `null` | 배경색 |
| `blockType` | string | `'paragraph'` | `'paragraph'`, `'ordered'`, `'bullet'`, `'h1'`~`'h3'`, `'page'` |
| `pageId` | string\|null | `null` | 페이지 블록일 때 연결된 페이지 ID |

## 4. 기능 명세 — 키보드 동작

### 4.1 Enter

| 커서 위치 | 동작 | 의도된 동작인가? |
|-----------|------|:---:|
| paragraph 맨 앞 | 현재 토글 **앞**에 빈 토글 삽입, 커서는 원래 텍스트에 유지 | O |
| paragraph 맨 끝 + 토글 열려있고 하위 토글 있음 | 하위 토글들의 **첫 번째 자식**으로 빈 토글 삽입 | O |
| paragraph 맨 끝 + 토글 닫혀있거나 하위 없음 | 현재 토글 **다음 형제**로 빈 토글 삽입 | O |
| paragraph 중간 | 텍스트 분할 — 커서 앞 텍스트는 현재 토글에, 뒤 텍스트는 새 형제 토글로 | O |
| NodeSelection 또는 CheckboxSelection 상태 | 아무 동작 안 함 (무시) | O |

- 새 토글은 부모 토글의 `isTodo` 속성을 상속한다.

### 4.2 Shift+Enter

- 블록 내부에서 줄바꿈 (hard break / soft newline). 새 토글을 만들지 않는다.

### 4.3 Backspace

| 상태 | 동작 | 의도된 동작인가? |
|------|------|:---:|
| 멀티셀렉트 활성 | 선택된 블록 전체 삭제 (중첩 필터링 적용) | O |
| 투두 토글 + 커서가 블록 시작 | **투두 해제** (체크박스 제거). 내용은 유지 | O |
| 빈 토글 + 하위 토글 없음 | 토글 블록 자체 삭제, 커서를 이전 블록 끝으로 이동 | O |
| 문서 첫 블록 + 내용 있음 | 토글 해제 → 내부 콘텐츠(paragraph + 하위 토글)를 토글 밖으로 풀어냄 | O |
| 내용 있음 + 이전 블록 있음 | 토글 해제 → 첫 paragraph 내용을 이전 블록 끝에 병합, 하위 토글은 형제로 재배치 | O |
| 이전 블록이 토글인 경우 | 재귀적으로 가장 깊은 마지막 하위 토글을 찾아 그 끝에 병합. 접힌 토글은 자동으로 열림 | O |
| 커서가 블록 시작이 아닌 경우 | ProseMirror 기본 동작 (텍스트 삭제) | O |

### 4.4 Tab (들여쓰기)

| 조건 | 동작 | 의도된 동작인가? |
|------|------|:---:|
| 이전 형제가 토글 | 현재 토글을 이전 형제 토글의 **마지막 자식**으로 이동. 닫혀있으면 자동으로 열림 | O |
| 이전 형제가 없음 (첫 번째 자식) | 아무 동작 안 함 | O |
| 이전 형제가 토글이 아님 | 아무 동작 안 함 | O |

### 4.5 Shift+Tab (내어쓰기)

| 조건 | 동작 | 의도된 동작인가? |
|------|------|:---:|
| 부모 토글이 있음 | 현재 토글을 부모 토글 **다음 형제**로 이동 | O |
| 이미 최상위 | 아무 동작 안 함 | O |

### 4.6 화살표 키

| 키 | 상태 | 동작 |
|----|------|------|
| ← | paragraph 시작 + 투두 | CheckboxSelection으로 전환 (체크박스 선택) |
| ← | paragraph 시작 + 일반 | NodeSelection으로 전환 (토글 화살표 선택) |
| ← | CheckboxSelection | NodeSelection으로 전환 |
| → | CheckboxSelection | paragraph 시작으로 복귀 (TextSelection) |
| → | NodeSelection (토글) | paragraph 시작으로 진입 (TextSelection) |
| ↑ | CheckboxSelection | 이전 보이는 투두 블록의 체크박스로 이동 |
| ↑ | NodeSelection | 이전 보이는 토글의 화살표로 이동 |
| ↓ | CheckboxSelection | 다음 보이는 투두 블록의 체크박스로 이동 |
| ↓ | NodeSelection | 다음 보이는 토글의 화살표로 이동 |

- 접힌(closed) 토글의 하위 블록은 건너뛴다.

### 4.7 Cmd/Ctrl+A (전체 선택)

| 호출 횟수 | 동작 |
|-----------|------|
| 1회 | 현재 paragraph 텍스트만 선택 |
| 2회 | 현재 토글 전체 선택 (하위 포함) |
| 3회 | 다시 paragraph 텍스트로 순환 |

## 5. 기능 명세 — 복사/붙여넣기

### 5.1 클립보드 변환 규칙

| 처리 단계 | 조건 | 동작 |
|-----------|------|------|
| `transformCopied` | 첫 노드가 토글 | `Slice(content, 0, 0)` — 인라인 병합 방지, 블록 단위 보장 |
| `transformPasted` | 첫 노드가 토글 | `Slice(content, 0, 0)` — 동일 |

### 5.2 handlePaste 동작

| 붙여넣기 내용 | 동작 | 의도된 동작인가? |
|--------------|------|:---:|
| 토글 블록 | 현재 토글의 **다음 형제**로 삽입 (중첩 없음) | O |
| 단일 텍스트블록 | ProseMirror 기본 처리 — 커서 위치에 **인라인 삽입** | O |
| 여러 블록 | 첫 블록: 커서 위치에 인라인 삽입. 나머지: 각각 토글로 감싸서 **형제로 삽입** | O |

- 투두 토글 안에서 붙여넣기하면 새 토글도 투두 속성을 상속한다.

### 5.3 멀티셀렉트 복사/잘라내기

- Cmd/Ctrl+C: 선택된 토글들을 `Slice(Fragment.from(nodes), 0, 0)`로 직렬화
- Cmd/Ctrl+X: 복사 후 선택 블록 삭제

## 6. 기능 명세 — 블록 드래그 앤 드롭

### 6.1 기획 의도

바탕화면에서 **파일을 폴더에 넣듯이**, 드래그 핸들(⠿)을 잡고 다른 토글 블록 위에 호버링 후 드롭하면 해당 토글의 **하위 자식**으로 들어간다. 이 경험은 블록을 Tab 키로 들여쓰기하는 것과 동일한 결과를 내지만, 마우스로 직관적으로 조작할 수 있다.

### 6.2 구현 흐름

| 단계 | 구현 위치 | 동작 |
|------|----------|------|
| dragstart | 드래그 핸들 DOM 이벤트 | NodeSelection 설정, JSON을 `application/x-thinkmap-block`에 저장, `window.__crossPaneDrag` 설정, `view.dragging` 설정 |
| dragover | NodeView DOM 이벤트 | 블록 드래그 감지 → 헤더 36px 영역 위일 때 `toggle-drop-target` 클래스 추가 (시각적 피드백) |
| 호버링 600ms | dragover 내 setTimeout | 닫힌 토글 자동 열기 |
| drop | NodeView DOM 이벤트 | 소스 블록 삭제 → 대상 토글의 마지막 자식으로 삽입. 크로스 패널 지원 |
| dragend | 드래그 핸들 DOM 이벤트 | `block-dragging` 클래스 제거, 플러그인 상태 초기화 |

### 6.3 블록 드래그 vs 텍스트 드래그 구분

| 조건 | 블록 드래그 (핸들) | 텍스트 드래그 (브라우저) |
|------|-------------------|----------------------|
| `application/x-thinkmap-block` | 설정됨 (dragstart에서) | 없음 |
| `editor.state.selection` | `NodeSelection` | `TextSelection` |
| `window.__crossPaneDrag` | 설정됨 | null |
| 처리 경로 | NodeView `drop` 이벤트 | Plugin `handleDrop` prop |

**주의:** ProseMirror의 dragstart 핸들러가 dataTransfer를 덮어쓰기 때문에 `application/x-thinkmap-block`이 types에서 사라질 수 있다. 따라서 `NodeSelection` 타입 체크를 병행해야 한다.

### 6.4 알려진 이슈 및 디버깅 기록

> A, B, C, D 모두 해결됨 (2026-04-10). 상세 해결 내용은 섹션 11 참조.

#### 이슈 B: ProseMirror dataTransfer 덮어쓰기 (해결)

**현상:** 드래그 핸들의 dragstart에서 `e.dataTransfer.setData('application/x-thinkmap-block', ...)`을 설정하지만, ProseMirror의 dragstart 핸들러가 이후 실행되면서 커스텀 타입이 사라짐.

**해결:** dragover/drop에서 `application/x-thinkmap-block` 외에 `NodeSelection` 타입 체크를 병행:
```
const isBlockDrag = types.includes('application/x-thinkmap-block')
  || (view.dragging && selection instanceof NodeSelection)
  || window.__crossPaneDrag
```

## 8. 기능 명세 — 입력 규칙 (InputRule)

## 10. 콘텐츠 모델 제약사항

| 허용 | 불가 |
|------|------|
| 토글 내부에 paragraph | 토글 내부에 bulletList |
| 토글 내부에 하위 토글 (중첩) | 토글 내부에 orderedList |
| 토글 내부에 hard break (Shift+Enter) | 토글 내부에 listItem |
| | 토글 내부에서 `> ` 입력으로 중첩 토글 생성 |

- 넘버링(`blockType: 'ordered'`/`'bullet'`)은 토글의 **시각적 속성**으로만 존재하며, 실제 ProseMirror 리스트 노드는 사용하지 않는다.
- 토글의 첫 번째 자식은 반드시 paragraph이어야 한다 (헤더 텍스트 역할).

## 11. 해결된 이슈 기록

### 11.1 텍스트 복사 붙여넣기 중첩 (2026-04-02, 해결)

**현상:** 토글 내부 텍스트를 Cmd+C → 다른 토글에서 Cmd+V → 토글이 중첩됨.

**원인:** 클립보드 HTML에 토글 DOM이 포함되어 `toggle > toggle > paragraph` 구조가 생성. `handlePaste`가 이를 "토글 블록 복사"로 판단.

**해결:**
1. `transformPasted` — 단일 토글 체인(`toggle > toggle > ... > paragraph`)은 텍스트 복사로 판단, paragraph만 추출
2. `handlePaste` — 단일 paragraph는 inline content를 `$from.pos`에 직접 삽입
3. NodeView `dragover` — `editor.view.dragging` 체크 제거, 텍스트 드래그를 `handleDrop` plugin으로 위임

### 11.2 ProseMirror dataTransfer 덮어쓰기 (2026-04-02, 해결)

**현상:** 드래그 핸들이 설정한 `application/x-thinkmap-block`이 dragover에서 보이지 않음.

**원인:** ProseMirror의 dragstart 핸들러가 커스텀 타입을 덮어씀.

**해결:** dragover/drop에서 `NodeSelection` 타입 체크를 병행:
```
isBlockDrag = types.includes('application/x-thinkmap-block')
  || (view.dragging && selection instanceof NodeSelection)
  || window.__crossPaneDrag
```

### 11.3 블록 드롭 실패 시 토글 분해 — Issue D (2026-04-10, 해결)

**현상:** NodeView drop이 처리하지 못한 케이스에서 PM 기본 핸들러가 동작하여 토글이 bare paragraph로 분해됨. 분해된 paragraph는 화살표/핸들/체크박스가 없고 백스페이스/InputRule이 정상 동작하지 않음.

**해결 (defense in depth):**
1. **Plugin `handleDrop` 폴백** — 토글 슬라이스가 빈 영역(NodeView drop이 잡지 못하는 영역)에 드롭되면 그 위치의 가장 가까운 토글 다음 형제로 삽입. PM 기본 핸들러로 떨어지는 경로 차단.
2. **`appendTransaction` 정규화 안전망** — 토글의 첫 자식(헤더 paragraph) 외에 bare paragraph가 발견되면 자동으로 toggle 노드로 감싸기. 어떤 경로로 분해되어도 즉시 복구.

### 11.4 dragleave 플리커링 — Issue A (2026-04-10, **미해결**, 시도 기록 보관)

**현상:** 드래그 중 토글의 자식 요소(.toggle-button, .toggle-drag-handle, .toggle-todo-checkbox 등) 위로 마우스가 들어갈 때마다 .toggle-block에서 dragleave 발생 → `toggle-drop-target` 클래스가 깜빡이거나 시각효과가 보이지 않음.

**원인:** 자식 요소가 dragenter/leave 이벤트의 별도 타겟이 됨. relatedTarget이 null인 경우도 있어 `dom.contains()` 체크 실패.

#### 시도 1 (실패): 모든 자식 요소에 `pointer-events: none` 적용

```css
.tiptap-editor.block-dragging .toggle-block * { pointer-events: none !important; }
.tiptap-editor.block-dragging .toggle-block .toggle-block { pointer-events: auto !important; }
.tiptap-editor.block-dragging .toggle-drag-handle { pointer-events: auto !important; }
```

- **결과**: 처음에는 enter-target 클래스가 추가되지만 즉시 dragleave가 발생해 화면에 보이지 않음. computed style로는 outline rgb(255,0,0) solid 8px와 background lime이 정확히 적용된 것이 확인됐지만 시각적으로 보이지 않음.
- **추가 시도**: position:fixed 빨간 박스를 body에 직접 부착(z-index 999999) — 이것조차 보이지 않음.
- **흔적**: 탭 제목(`document.title`)을 호버 시 변경하니 "한 번씩 깜박"이는 것이 관찰됨 → enter가 즉시 leave로 취소됨이 확인.
- **결론**: 모든 핸들에 pointer-events: auto를 주면 *타겟* 토글의 핸들도 활성화되어 자식 진입 시 dragleave가 부모에서 발생하는 것이 원인.

#### 시도 2 (실패): source 핸들에만 pointer-events 활성화 (`drag-source` 클래스)

`dragstart`에서 `drag-source` 클래스를 추가하고 CSS를 `.toggle-drag-handle.drag-source { pointer-events: auto }`로 변경.

- **결과**: 핸들 드래그 시 dragover 이벤트 자체가 발화하지 않음 (글로벌 capture-phase 리스너에서도 잡히지 않음). 텍스트 드래그(블록 안쪽 텍스트 잡기)는 발화함.
- **부수 발견**: 텍스트 드래그가 stale `window.__crossPaneDrag` 와 `NodeSelection` 때문에 블록 드래그로 오인되는 또 다른 버그 발견 → `dragend`에서 stale state 정리하여 수정.
- **결론**: 원인 미상. CSS pointer-events 접근 자체가 핸들 드래그의 dragover 발화를 막는 부작용이 있음.

#### 시도 3 (현재 코드, 미검증): debounce 방식 dragover

CSS pointer-events 접근을 모두 폐기하고, dragleave 핸들러도 제거. 대신 dragover에 100ms debounce를 적용:

```js
// dragover가 계속 오면 timer 리셋, 100ms 동안 안 오면 떠난 것으로 판단
if (dragoverDebounceTimer) clearTimeout(dragoverDebounceTimer)
dragoverDebounceTimer = setTimeout(() => clearDropTimers(), 100)
```

- **이론**: 자식 진입 시 dragleave가 발생해도 dragover가 계속 부모에 오므로 100ms debounce가 timer를 리셋해 클래스가 유지됨. 진짜로 떠나면 dragover가 끊겨 100ms 후 정리.
- **상태**: 코드 적용했으나 사용자 검증 전. 다음 세션에서 확인 필요.

#### 부수 수정 (확정): dragend stale state cleanup

`dragend` 핸들러에서 `window.__crossPaneDrag = null`과 `editor.view.dragging = null`을 명시적으로 정리. 이전에는 cancelled drag 후 stale state가 남아 다음 텍스트 드래그가 블록 드래그로 오인되는 버그가 있었음.

#### 다음 세션 진단 필요 사항

1. 시도 3 (debounce 방식)이 실제로 동작하는지 확인 — 아직 시각효과 검증되지 않음
2. 만약 debounce도 실패하면, dragover가 어디까지 도달하는지 글로벌 capture-phase 리스너로 다시 추적
3. 위 모든 것이 실패하면, NodeView 자체를 재구성 — 헤더 영역만 별도 div로 감싸서 그 위에서만 드롭 처리

### 11.5 drop 위치 RangeError 및 스코프 버그 — Issue C (2026-04-10, 해결)

**현상:** `doc.nodeAt(getPos())`에서 `Index N out of range` 에러. 또한 NodeView drop 핸들러의 try 블록 안에 `const crossDrag` 선언이 있어 try 블록 밖의 cross-pane cleanup 코드에서 ReferenceError 발생.

**해결:**
1. **스코프 버그 수정** — `crossDrag` 선언을 try 블록 밖으로 이동하여 cleanup 코드에서 접근 가능하도록 함. (이전: try 안에서 `const crossDrag` 선언 → 밖에서 사용 시 ReferenceError 발생, 매 드롭마다 silent error)
2. **위치 검증 강화**:
   - `Number.isInteger(pos) && pos >= 0 && pos < doc.content.size` 체크
   - `doc.nodeAt()` 호출도 try/catch로 보호
   - 매핑된 대상 위치 재검증
   - 소스 위치도 재검증 후 삭제
3. **`finally`로 cleanup 보장** — `editor.view.dragging = null`을 finally에 옮겨 어떤 경로로든 정리 보장.

## 13. 설계 원칙 — 콘텐츠 삽입 경로

ProseMirror에서 콘텐츠가 에디터에 삽입되는 경로는 **3가지**이며, 각각 별도로 제어해야 한다:

| 경로 | ProseMirror prop | 현재 상태 |
|------|-----------------|-----------|
| Cmd+V 붙여넣기 | `handlePaste` | 해결됨 (2026-04-02) |
| 텍스트 드래그 드롭 | `handleDrop` plugin prop | 해결됨 (2026-04-02) |
| 블록 드래그 드롭 (D, C: 데이터/RangeError) | NodeView `drop` + Plugin `handleDrop` 폴백 + `appendTransaction` 정규화 | 해결됨 (2026-04-10) — 섹션 11.3, 11.5 |
| 블록 드래그 드롭 (A: 시각 피드백) | dragover debounce 방식 (시도 3) | **미해결** — 섹션 11.4 |

**원칙:**
- 콘텐츠 삽입 문제는 반드시 **ProseMirror가 제공하는 표준 plugin prop**(`handlePaste`, `handleDrop`, `transformPasted` 등)으로 해결한다.
- DOM을 직접 읽거나 강제로 조작하는 방식은 지양한다. ProseMirror의 state-driven 모델을 따른다.
- 새로운 삽입 경로가 발견되면 이 표에 추가하고 해당 prop에서 처리한다.

## 15. 수정 원칙

1. **명시적 핸들러(handlePaste, handleDrop, transformPasted 등)는 검증 없이 건드리지 않는다** — 이미 잘 작동하는 경로
2. **ProseMirror 기본 경로에서 발생하는 중첩만 차단한다** — ProseMirror 표준 plugin prop 사용
3. **스키마(`content`, `group`)는 변경하지 않는다** — 넘버링 차단 등 다른 제약이 이 스키마에 의존
4. **DOM을 직접 읽거나 강제로 조작하지 않는다** — ProseMirror의 state-driven 모델을 따른다

## 16. 수정 전 체크리스트

코드 변경 후 아래 시나리오를 **모두** 수동 테스트할 것:

- [ ] 토글 안에서 텍스트 1줄 Cmd+V → 인라인 삽입 (토글 중첩 없음)
- [ ] 토글 안에서 텍스트 3줄 Cmd+V → 형제 토글 3개 생성 (중첩 없음)
- [ ] 토글 블록 복사 → 토글 안에서 Cmd+V → 형제로 삽입 (중첩 없음)
- [ ] 멀티셀렉트 3개 → Cmd+C → Cmd+V → 형제 3개 삽입
- [ ] 토글 안에서 넘버링 시도 → 적용 안 됨 (스키마 제약 유지)
- [ ] 외부(브라우저 등)에서 복사한 텍스트 → 토글 안에서 Cmd+V → 정상 삽입
- [ ] 텍스트 드래그 → 다른 토글에 드롭 → 인라인 삽입 (중첩 없음)
- [ ] 같은 토글 안에서 텍스트 드래그 이동 → 원본 삭제 + 드롭 위치에 삽입
- [ ] 블록 드래그 핸들(⠿) → 다른 블록 헤더 위 호버링 → 하이라이트 표시
- [ ] 블록 드래그 핸들(⠿) → 다른 블록에 드롭 → 하위 토글로 삽입 + 원본 삭제
- [ ] 블록 드래그 → 자기 자신에 드롭 → 무시 (아무 변화 없음)
- [ ] 블록 드래그 실패 시 → 토글이 일반 텍스트로 분해되지 않을 것
