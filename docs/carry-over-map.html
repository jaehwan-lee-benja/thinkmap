3. 이월 대상 판정 로직 extractCarryOverBlocks

※ child.blockType === 'h3' 인 경우 하위 섹션 내부도 재귀적으로 같은 로직 적용. (당일 이슈 등)

4. 이월 트리거 (언제 실행되나) 4가지 경로

EAGER 새 daily 페이지 생성
캘린더 "+" / "오늘" 버튼 / → 버튼
어제 페이지의 모든 이월 대상을 buildDailyPageTemplate() 에서 일괄 삽입
LAZY 기존 daily 페이지 열기
페이지 전환, 브라우저 탭 복귀, QuickTodo 삽입
어제 페이지와 비교해 신규 미이월만 syncCarryOver() 로 삽입
THREAD 체크박스 완료/해제 동기화
어느 페이지에서든 todo 토글 시
같은 originBlockId 을 공유하는 최근 90일 이내 이월본 모두 동기화 (syncBlockAcrossPages)
DISMISS 이월본 삭제 → 재이월 차단
휴지통/Backspace/드래그/멀티셀렉트
block-dismissed 이벤트 → _dismissed 리스트에 추가. Lazy/Eager 모두 이 리스트 항목은 건너뜀

5. 섹션 3종 × 저장 채널 혼동 주의

🔷 고정 섹션 (fixed)

식별: section_type='fixed'
ID: fixed_todo, fixed_notice, fixed_wrapup, fixed_daily_issue
저장: worklog_sections 테이블 행
매 daily 생성 시 템플릿에서 자동 시드.
title·visibility 변경은 테이블에 반영 (master 한정 RLS).

📌 사용자 pinned 섹션

식별: attrs.isPinned === true
ID: sec_xxxxxxxx (자동 생성)
저장: content_tiptap 내부만
어제 content_tiptap → 내일 content_tiptap 으로 복사.
중간 하루라도 pinned 없으면 체인 끊김.

⚪ 임시 섹션

식별: attrs.isPinned === false
ID: sec_xxxxxxxx
저장: 해당 daily 페이지에만
이월 안 됨.
핀 클릭하면 pinned 섹션으로 승격.

6. 권한 (visibility) × 이월 자물쇠

🔓 visibility = 'all' (기본)

  • 모든 인증 계정이 열람·편집
  • 이월 시 속성 그대로 복사 → 내일도 'all'
  • 특별한 저장 경로 없음

🔒 visibility = 'master' (마스터 전용)

  • master 계정만 보임 (load 시 비관리자에게 필터링)
  • 비관리자 저장 시 master 섹션은 DB에서 merge 보존 (data loss 방지)
  • 이월 시 속성 유지 → 다음 날도 master 전용
  • fixed 섹션: worklog_sections.visibility='master' 저장
  • pinned 섹션: content_tiptap 안 attrs.visibility='master' 저장

7. 실전 시나리오 예시 타임라인

A. 미완료 투두 연쇄 이월 → Thread 동기화로 일괄 완료

04/21›todo "구매 요청" 작성 (원본, blockId: abc)
04/22›[이월 04/21] "구매 요청" 이월본 #1 (originBlockId: abc)
04/23›[이월 04/21] "구매 요청" 이월본 #2 (originBlockId: abc) ← 최초 원본 추적
04/24›어느 페이지든 체크 → 90일 이내 같은 originId 모두 ✓

B. master + pinned 섹션 연쇄 계승

04/23›"새 섹션" 추가 + 🔒(master) + 📌(pin)
04/23›content_tiptap 에 h2 attrs.visibility='master', isPinned=true 저장
04/24›→ 버튼으로 내일 생성 → pinned 섹션 이월 → 섹션 전체 복사
04/25›생성 시 04/24에서 또 이월 → 계속 유지

C. 이월본 삭제 후 재이월 차단

04/22›"주문하기" todo 미완료
04/23›[이월 04/22] "주문하기" 생성
04/23›사용자 삭제 → _dismissed 에 blockId + originBlockId 추가
04/23›페이지 재방문 → Lazy 이월이 _dismissed 확인 후 재삽입 안 함
04/24›내일 생성 → 04/23 의 _dismissed 계승 → 04/22 원본 "주문하기" 재이월 차단

9. 개선 후보 (토론 기준) roadmap

⚡ 기능 확장

  • 과거 방향 "어제 할 일 불러오기" 수동 버튼
  • _dismissed 항목 복원 UI
  • 이월 범위 필터 (특정 섹션만)
  • 주/월 단위 이월 사이클
  • 이월 누적 통계 대시보드

🛡️ 신뢰성

  • pinned 섹션 중앙 저장 (worklog_sections 활용)
  • 이월 감사 로그 (언제·어디서 왔는지 추적)
  • _dismissed 만료 정책 (N일 후 자동 소거)
  • 이월 무결성 자동 검증 스크립트

🎨 UX

  • 연쇄 이월 시각화 강화 (최초 원본 날짜 배지)
  • 이월본→원본 네비게이션 (클릭 점프)
  • 묵은 할일 경고 (N일 이상)
  • 자물쇠 + 핀 원클릭 설정
  • 섹션 순서 드래그 중 이월 블록 시각적 분리

🔐 권한

  • 섹션별 편집 권한 세분화
  • user-group 한정 섹션
  • 변경 감사 로그 (누가·언제·무엇)
  • master 외 계정의 읽기 전용 모드
