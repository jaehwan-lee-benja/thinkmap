# ThinkMap 모바일 디자인 기준

> 작성일: 2026-05-07
> 작성자: jaehwan-lee-benja
> 목적: 모바일에서도 데스크톱과 동일한 기능을 사용할 수 있도록 한다. 시각적 화려함보다 **기능적 정합성**을 우선한다.
> 이후 모든 UI 작업은 본 문서의 원칙을 따른다.

---

## 0. TL;DR

- **기능 = 데스크톱 동등**. 화면이 작다고 기능을 빼지 않는다.
- 가로 스크롤 회피, 자동 줄바꿈/축약 우선.
- hover 의존 UI 는 모바일에 다른 트리거 제공.
- 새 컴포넌트는 **mobile-first**. 데스크톱 보강은 `min-width` 미디어 쿼리.

---

## 1. 원칙

### 1.1 기능 = 데스크톱 동등
데스크톱에서 가능한 동작은 모바일에서도 가능해야 한다. 같은 동작을 다른 진입점으로 제공해도 된다 (예: 호버 메뉴 → 탭 메뉴). 단, **기능 자체가 사라지면 안 된다**.

### 1.2 가로 스크롤 회피
viewport 폭을 넘는 컨텐츠는 자동 줄바꿈 / 축소 / 세로 재배치. 가로 스크롤은 의도된 데이터 (큰 테이블 등) 외에는 발생하지 않아야 한다.

### 1.3 터치 타겟
클릭 가능 요소는 **최소 36 × 36 px**. iOS HIG 기준은 44 px 이지만 정보 밀도가 높은 이 앱은 36 px 로 타협. 그보다 작은 요소는 패딩으로 hit area 확장.

### 1.4 호버 회피
호버 의존 UI 는 모바일에서 다른 트리거 제공.
- hover 시 노출되는 액션 버튼 → 모바일은 항상 노출하거나, 길게 누름 (long press) / 탭으로 메뉴 표시.
- hover tooltip → 모바일은 탭 시 표시 또는 라벨 항상 노출.

### 1.5 폰트 / 패딩
- 본문 입력 필드 폰트 **16 px 이상** (iOS 의 자동 줌 회피).
- 모바일에서 패딩/마진은 데스크톱 대비 ~70% 로 축소.
- 라벨/메타 정보는 11~12 px 까지 허용.

## 2. Breakpoints

```css
/* mobile  */ @media (max-width: 767px) { ... }
/* tablet  */ @media (min-width: 768px) and (max-width: 1023px) { ... }
/* desktop */ @media (min-width: 1024px) { ... }
```

표준 검증 폭: **360 / 768 / 1024 / 1440**. 새 UI 변경 후 네 폭에서 모두 정상 동작 확인.

## 3. 레이아웃 패턴

### 3.1 사이드바
- **모바일**: 오버레이 (본 콘텐츠 위에 겹침). 외부 탭 / 닫기 버튼으로 닫힘.
- **태블릿**: 슬라이드 또는 영구 분할. 가용 폭에 따라.
- **데스크톱**: 영구 분할.

### 3.2 캘린더
- 7 × N 그리드. 셀 폭 = `(viewport_width - padding) / 7`.
- 모바일 (360 px) 기준 셀 ≈ 48 px. **셀 안에 날짜 + 작은 메타 (점 / 배지) 만**.
- 텍스트 미리보기는 데스크톱(≥ 1024 px) 만.
- 가로 스크롤 X — 셀이 viewport 밖으로 나가면 안 됨.

### 3.3 업무일지 카드 (h2 섹션)
- 카드 좌우 마진 모바일에서 0 또는 4 px.
- 카드 내부 패딩 12 → 8 px.
- 섹션 헤더 + 카드 본문이 한 줄에 안 들어가면 헤더가 별도 줄.

### 3.4 토글 액션 버튼 (드래그 / 코멘트 / 잠금 / 삭제 등)
모바일에서 호버 의존 → 다른 노출 방식. 우선순위:
1. **드래그 핸들** (재정렬 — 필수)
2. **코멘트** (사용자 가시 가치 — 필요 시 표시)
3. **이월/중복 태그** (정보 표시 — 텍스트 옆 줄바꿈)
4. **마스터 전용 토글 / 별 / 삭제** (특수 모드만)

화면이 좁으면 우선순위 낮은 것부터 숨김. 단, 마스터 모드 / 편집 중에는 펼쳐진 메뉴로 노출.

### 3.5 이월 태그 / 카드 안 메타
- 같은 줄에 텍스트 + 태그 여러 개 → **`flex-wrap: wrap`** 또는 텍스트 `text-overflow: ellipsis`.
- 태그가 본문 위에 잘리거나 겹치면 안 됨.
- 태그 글자 11 px, 패딩 2~4 px.

### 3.6 모달
- 모바일: 화면 전체 또는 90vh. 외부 영역 X (overlay 풀 화면).
- 데스크톱: 중앙 정렬, max-width 정의.

### 3.7 코멘트 popover
- 모바일: 화면 하단 sheet 형태 (bottom sheet). anchor 옆 fixed 는 화면 좁을 때 어색.
- 데스크톱: anchor 옆 fixed.
- 본 앱: 폭 < 600 px 면 sheet 모드, 그 이상이면 floating panel.

## 4. 인터랙션

### 4.1 터치 우선
- `mousedown` 대신 `click` 또는 `touchstart + click`.
- iOS 의 300ms 지연 회피 (touch-action: manipulation).
- long press: ~500 ms. 컨텍스트 메뉴 등에 활용.

### 4.2 키보드
- 입력 필드 focus 시 가상 키보드가 화면 절반 차지.
- focus 시 viewport 자동 스크롤로 입력 필드를 키보드 위로 노출.
- 가상 키보드 위 toolbar (예: 코멘트 작성 버튼) 는 fixed positioning + safe-area 고려.

### 4.3 제스처
- 스와이프로 사이드바 닫기 / 페이지 이동 등은 **선택 사항**. 명시적 버튼이 우선.
- 길게 누름은 컨텍스트 메뉴 / 다중 선택 트리거.

---

## 5. 콘텐츠 우선순위

### 5.1 본문 우선
daily 페이지 본문, 일반 페이지 에디터 — 한 줄 컬럼 + 다른 패널은 부수적.

### 5.2 점진 제거
화면이 좁아지면 시각 장식 (그림자, 보조 라벨, 배경 그라데이션) 부터 제거. 데이터/액션은 유지.

### 5.3 단일 진입점 단순화
모바일에서 한 화면 = 한 행동. 동시 다중 패널 (사이드바 + 본문 + 코멘트) 은 데스크톱 전용.

## 6. 구현 체크리스트

새 UI / 변경 시 검증할 항목:

- [ ] `<meta name="viewport" content="width=device-width, initial-scale=1">` (이미 박힘)
- [ ] body / html `overflow-x: hidden`
- [ ] 모든 클릭 요소 ≥ 36 × 36 px
- [ ] hover-only 액션은 모바일 트리거가 있는가?
- [ ] long text 자동 줄바꿈 또는 ellipsis
- [ ] 가로 스크롤 발생 X (의도된 외)
- [ ] 입력 필드 폰트 ≥ 16 px
- [ ] 모바일에서 사이드바 오버레이 동작
- [ ] 모바일에서 캘린더 셀이 viewport 안
- [ ] 모달이 모바일에서 풀 화면

## 7. 변경 적용 지침

1. **mobile-first**: 기본 CSS 가 모바일 형태. 데스크톱 보강은 `@media (min-width: 1024px)`.
2. 데스크톱-only CSS 는 명시적 미디어 쿼리.
3. 변경 후 **360 / 768 / 1024 / 1440** 네 폭에서 모두 작동 확인.
4. 변경 PR / 커밋 메시지에 "모바일 검증 완료" 표시 (또는 미검증 사유).

## 8. 알려진 이슈 (현재 작업 이전 미해결)

| 이슈 | 진단 |
|---|---|
| 캘린더 가로 날짜 잘림 | 셀 폭이 viewport 보다 커서 우측 일부 보이지 않음. 모바일 폰트/패딩 축소 + grid 셀 min-width 제거 필요 |
| 이월 태그 겹침 | 카드 안에서 텍스트 + 태그가 같은 줄에 박혀 좁은 화면에서 overlap. `flex-wrap: wrap` + 태그 위치 분리 필요 |
| 토글 액션 버튼 보이지 않음 (모바일) | hover 의존 → 모바일은 hover X. 항상 노출 또는 long-press 메뉴로 |
| 사이드바 영구 분할 | 모바일에서 좁은 본문 — overlay 모드 필요 |
| 코멘트 popover 좁음 | anchor 옆 fixed 라 모바일에서 화면 잘림. bottom sheet 모드 필요 |

---

## 9. 우선순위 (이번 모바일 작업 진행 순서)

1. **캘린더 가로 잘림** — 가장 자주 보는 화면. 즉시 fix.
2. **이월/중복 태그 겹침** — 본문 가독성.
3. 토글 액션 버튼 모바일 노출 정책 — hover-only 검토 + 항상 노출 또는 메뉴.
4. 코멘트 popover bottom sheet 모드.
5. 사이드바 / 모달 모바일 검증.

각 단계 후 360 px 폭에서 검증 + 데스크톱 회귀 확인.
