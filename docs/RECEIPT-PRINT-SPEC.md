# 영수증 인쇄 명세서 (RECEIPT-PRINT-SPEC)

> 멤버십 키오스크 참여권 영수증의 **인쇄 파이프라인 정본**.
> 컷·여백 관련 코드를 고치기 전에 이 문서를 읽고, 고친 뒤에는 §9 체크리스트를 통과시킨다.
> 최초 작성 2026-08-09(구조 라운드 — 유저: 「영수증 컷트는 계속 불안정한 감이 있는데. 구조적인 점검과 리팩토링 들어가자」).

---

## 1. 왜 이 문서가 있는가

컷 문제가 세 번 재발했다. 그때마다 개별 패치로 덮었고, 그래서 네 번째가 왔다.

| 시점 | 증상 | 그때의 처방 | 남은 구멍 |
|---|---|---|---|
| 8/06 | 다시 인쇄 시 컷 안 됨 | 래스터 페이로드 축소(빈 행 trim, 큰 글씨 m=3) | 컷이 스트림 맨 끝이라 **절단되면 컷부터 사라진다**는 성질은 그대로 |
| 8/06 | 옛 저장본에 컷 블록이 없어 안 잘림 | 컷 불변 조항(블록이 없어도 강제 컷) | 저장본이 **통째로** 코드를 이기는 구조는 그대로 |
| 8/08 | 컷 미작동 | 컷 방언을 값으로 뺌(`feed`/`full`/`partial`) | 성공한 값이 **그 기기에만** 남는다 |
| 8/08 | 컷 뒤 빈 종이 1장이 따로 잘림 | (컷 1회 실측 → RawBT 축 판정) | **컷 주체가 둘일 수 있는데 「맡긴다」를 코드로 표현할 수 없었다** |

공통 원인은 개별 버그가 아니라 **구조**였다:
「무엇이 정본인가」가 코드에 없고 기기 localStorage 에 있었다. 그래서 같은 코드가 기기마다 다른 종이를 뱉었고,
결과를 알 수 없는(RawBT 스킴) 경로인데 **입력 조건조차 기록하지 않아** 매번 추측으로 시작했다.

## 2. 파이프라인 — 계층과 소유

```
    영수증 «모양»                프린터 «성질»
  receiptTemplate.js            printerConfig.js
  블록 순서·문구·폭             컷 방언 · 스킴 호출 방식
  = 매장 공통                   = 이 기기 고유
        └──────────┬──────────────────┘
                   ▼
              buildEscpos(tpl, data, cfg)      ← 바이트 생성(한 벌)
                   ▼
        print.js  printReceipt(data, opts)     ← ★인쇄의 유일한 진입점
                   ├─ openScheme  → rawbt:base64,…
                   └─ logPrint    → printLog.js (블랙박스 20건)
```

**규율 1 — 진입점은 하나.** 발권·재인쇄·회수·자동 브리지·편집기 테스트 인쇄가 **모두** `printReceipt` 를 지난다.
편집기만 우회하던 종전 구조에서는 「테스트는 나오는데 실제는 안 된다」류 신고에서 경로 차이를 배제할 수 없었다.

**규율 2 — 정본은 코드에 있다.** 저장분(localStorage)은 «기본값과 다른 것»의 목록일 뿐이다(§4).

**규율 3 — 성공을 주장하지 않는다.** `rawbt:` 스킴은 결과를 알려주지 않는다.
`ok=true` 는 **호출을 시도했다**는 뜻이다. 화면 문구도 «요청함 / 종이 확인»까지만 말한다.
결과를 못 남기니 **입력 조건을 전부 남긴다**(§6).

## 3. 바이트 계약

### 3.1 전체 순서

```
ESC @                        초기화 (1b 40)
[블록 순회]                  아래 3.2
(컷 블록이 없었고 cut≠none)  LF LF + 컷      ← 불변 조항(§3.4)
```

### 3.2 블록별 바이트

| 블록 | 브라우저(래스터) | node·구형(텍스트 폴백) |
|---|---|---|
| `logo` | `ESC $ x` + `GS v 0` 래스터(「사르르목장」) | `ESC E 1` + UTF-8 + LF |
| `text` | 같음(캔버스에 한글 폰트 → 1비트 래스터) | `ESC E`/`GS !` + UTF-8 + LF |
| `barcode` | `GS h`(높이) `GS w`(모듈폭) `GS H 0`(HRI 끔) `GS k 73 len {B<token>` | 동일(프린터 네이티브) |
| `token` | UTF-8 + LF | 동일 |
| `qr` | `GS ( k` 5시퀀스(모델2 → 크기 → 오류정정 L → 데이터 → 인쇄) | 동일 |
| `stamp` | 래스터(「스탬프 n/10」) | UTF-8 + LF |
| `feed` | `LF` × lines | 동일 |
| `cut` | §3.3 | 동일 |

★**텍스트만 래스터**다. 바코드·QR 은 **프린터 네이티브 그대로** 둔다 — 스캐너 판독이 실측 검증된 경로라
폰트 통일 이득보다 판독 리스크가 크다. (근거: 8/06 USB 유선은 raw 패스스루라 코드페이지에 한글이 없으면 모지바케.)

### 3.3 컷 방언 — `printerConfig.cut`

| 값 | 바이트 | 의미 | 언제 쓰나 |
|---|---|---|---|
| `feed`(기본) | `1d 56 42 00` | GS V 66 0 — 컷 위치까지 급지 후 부분컷 | 현대 기종 표준 |
| `full` | `1d 56 00` | GS V 0 — 급지 없는 풀컷 | 구형 기종이 아는 방언 |
| `partial` | `1d 56 01` | GS V 1 — 급지 없는 부분컷 | 위와 같음 |
| `none` | **미전송** | 컷을 우리가 보내지 않는다 | ★**RawBT/드라이버 자동 컷이 이미 자를 때** |

★`none` 이 왜 필요한가: RawBT 의 «Feed after print + auto cut» 이 켜져 있으면 우리 컷과 합쳐 **컷 2회**가 되고,
그 사이에 빈 조각이 따로 잘려 나온다(8/08 현장). **컷 주체는 하나여야 한다.**
종전 코드엔 「맡긴다」를 표현할 방법이 아예 없어서 이 문제를 구조적으로 고칠 수 없었다.

### 3.4 컷 불변 조항과 그 예외

- 저장된 템플릿에 `cut` 블록이 없거나 off 여도 **종이는 잘린다**(`LF LF` + 컷을 뒤에 붙인다).
  `validateTemplate` 은 폭·바코드만 보므로 컷 없는 옛 저장본이 그대로 통과해 왔다 — 「있어야 하는 것은 구조가 보장한다」.
- ★**단 `cut='none'` 은 예외다.** 그건 «컷을 안 냄»이 **의도**(RawBT 가 컷 주체)이므로,
  불변 조항이 그 의도를 덮으면 컷 2회 문제를 영원히 못 고친다.
  불변 조항은 «사고 방지»용이고, `none` 은 사고가 아니라 **선언**이다.

### 3.5 페이로드 크기와 절단

컷 명령은 **스트림 맨 끝 3~4바이트**다. URL 이 어디서 잘려도 **컷부터 사라진다** — 「다시 인쇄 시 컷 안 됨」의 실패 모드가 정확히 이것이었다.
그래서 크기를 계속 낮게 유지한다:

- 래스터 빈 행 trim(위·아래 잉크 없는 행 제거)
- 가로도 잉크 폭만 보내고 위치는 `ESC $`(절대 위치)로 지정
- 큰 글씨는 절반 해상도로 그려 `GS v 0` m=3(가로·세로 2배)로 확대 — 바이트 **1/4**

참고 실측(기본 템플릿, node 텍스트 폴백): `cut=feed` 385 bytes / `cut=none` 381 bytes.
브라우저 래스터 경로는 4.7KB 대(base64 6.3KB) — 로그의 `bytes` 열로 기기별·시점별 비교가 가능하다.

### 3.6 RawBT 스킴의 한계

- 호출 = `rawbt:base64,<base64(ESC/POS)>`
- **성공·실패를 알 수 없다.** 미설치·프린터 미선택·전송 실패가 전부 «조용한 무응답»이다.
- `location.href` 로 쏘면 스킴이 처리되지 않을 때 **현재 페이지가 오류 화면으로 바뀐다 = 키오스크 파괴**.
  `iframe` 은 같은 실패가 iframe 안에서 죽어 화면이 산다. → `printerConfig.scheme`(§4.2)

## 4. 설정과 저장 — 「정본 기본값 + 명시 오버라이드」

### 4.1 템플릿 (`mk-receipt-template`)

- 저장 형식 = **오버라이드 객체**. `diffFromDefault(tpl)` 가 기본값과 다른 키만 남긴다.
  - 순수 기본값이면 `{"version":3}` 하나만 저장된다(실측).
  - `width` 만 바꿨으면 `{"version":3,"width":58}` — `blocks` 는 저장되지 않는다
    ⇒ **코드에서 블록·문구를 개선하면 저장분이 있는 기기에도 그대로 흘러든다.**
- 읽기 = `mergeWithDefault(saved)` — 없는 키는 언제나 코드 기본값.
- 옛 저장본(v2 이하, 통째 저장)은 `migrateTemplate` 을 태워 **내용을 존중**한다.
  현장 태블릿이 손으로 맞춘 모양을 이 전환으로 날려버리지 않는다.

### 4.2 프린터 설정 (`mk-printer-config`) — 템플릿과 **별개 축**

| 키 | 기본값 | 값 |
|---|---|---|
| `cut` | `feed` | `feed`·`full`·`partial`·`none` (§3.3) |
| `scheme` | `auto` | `auto`(제스처 있으면 href, 없으면 iframe) · `iframe`(화면 안전) · `href` |

- 컷 방언·스킴은 «이 기기에 붙은 프린터의 성질»이라 **매장 공통 영수증 모양과 수명이 다르다**.
  그래서 저장 위치가 다르고, 편집기 [기본값](템플릿 복원)에도 딸려가지 않는다.
- 저장도 **기본값과 다른 값만**. 모르는 값은 조용히 기본값으로 떨어진다(오타·낡은 값이 살아남지 않게).
- 편집기에서 바꾸면 **즉시 저장**된다 — 「바꿨는데 저장을 안 눌러서 그대로였다」가 진단을 오염시키기 때문이다.

### 4.3 왜 `scheme` 기본값을 바꾸지 않았나

`iframe` 이 화면 파괴를 막는다는 건 분명하지만, **어느 방식이 이 기기에서 실제로 인쇄되는지는 현장 실물로만 갈린다**
(스킴은 결과를 안 알려준다). 방식을 코드가 혼자 바꾸면 최악의 경우 **인쇄가 전면 실패**한다.
⇒ 기본은 현행(`auto`) 유지 · 현장에서 전환 가능 · **어느 경로였는지 로그에 남긴다**.

## 5. 인쇄 경로(source) 인벤토리

| source | 화면 | 제스처 | 비고 |
|---|---|---|---|
| `claim` | 고객 태블릿 발권 직후(MemberCard) | 있음 | |
| `reprint` | 재인쇄 버튼(MemberCard / PrinterView 수동) | 있음 | 게이트 = 티켓 `state`(미스캔이면 허용) |
| `scan` | 카운터 회수 화면(ScanResultPanel) | 있음 | 직원 허브에서는 숨김(`allowPrint=false`) |
| `bridge` | 카운터 폰 자동 인쇄(PrinterView) | **없음** | ★제스처 없는 경로 — 스킴 차단 가능. 로그 `gestured` 로 갈린다 |
| `test` | 편집기 테스트 인쇄 | 있음 | 저장 전 템플릿·설정으로 쏜다(경로는 실인쇄와 동일) |

## 6. 블랙박스 (`mk-print-log`, 최근 20건)

「어느 기기·어느 설정·어느 페이로드였나」를 되살리는 표. 편집기 → [인쇄 기록]에서 보고 JSON 복사한다.

| 열 | 뜻 |
|---|---|
| `at` | ISO 시각 |
| `source` | §5 경로 |
| `cut` / `scheme` | 그때의 설정 |
| `resolved` | 실제로 쓰인 호출 경로(`href`·`iframe`·`preview`) |
| `tpl` | 템플릿 해시 — 기기 간 «같은 모양인가»를 한 눈에 |
| `bytes` / `b64` | 페이로드 크기(§3.5 — 절단과 직결) |
| `gestured` | 사용자 제스처가 살아 있었나 |
| `ok` / `reason` | **«시도했나»까지**(`no_token`·`build_failed`·`encode_failed`·`scheme_blocked`) |
| `tok` | 토큰 **끝 4자만** |

★개인정보: 토큰 전체를 남기면 로그가 곧 **재인쇄 가능한 참여권**이 된다. 이름·전화번호는 남기지 않는다.

**축 가르기 규칙**: 같은 `tpl`·`bytes`·`cut` 인데 종이 결과가 다르면 **기기·앱 축**(RawBT 설정·프린터).
`bytes` 나 `cut` 이 다르면 **우리 축**.

## 7. 현장 진단 순서 (컷·여백)

1. 편집기 → [인쇄 기록] → 마지막 줄의 `cut`·`bytes`·`tpl` 을 본다.
2. **종이가 안 잘린다** → 컷 방식을 `full` → `partial` 순으로 바꿔 [테스트 인쇄]. 잘리는 방언이 그 기종의 답이다.
3. **컷 뒤에 빈 조각이 따로 나온다** → 컷이 두 번이다(우리 + RawBT). → 컷 방식 **`컷 안 보냄`**.
   (반대로 RawBT 자동 컷을 끄고 우리 컷을 쓰는 선택도 같다 — **주체를 하나로 정하는 것**이 핵심.)
4. **아무것도 안 나온다** → 스킴 호출을 `주소 이동`/`iframe` 으로 바꿔 본다. 로그 `resolved`·`gestured` 확인.
   자동 인쇄(`bridge`)만 안 나오면 제스처 축이다.
5. **한글이 깨진다** → 래스터 경로가 아니다(브라우저가 아닌 환경). §3.2.

## 8. 수정 원칙

1. **바이트를 만드는 곳은 `buildEscpos` 하나다.** 화면·경로별로 따로 만들지 않는다.
2. **인쇄를 쏘는 곳은 `printReceipt` 하나다.** 편집기도 예외가 아니다.
3. **스킴을 발사하는 지점은 `openScheme` 하나다.** 프리뷰 차단 한 줄이 전 경로에 걸리는 이유가 이것이다.
4. 기기별로 달라질 값은 **`printerConfig` 에** 둔다. 템플릿에 섞지 않는다.
5. 저장분은 **오버라이드**다. 통째 저장을 되살리지 마라 — 그게 「낡은 저장본」의 원인이었다.
6. 「성공했다」고 쓰지 마라. 화면 문구는 «요청함 / 종이 확인»까지다.
7. RawBT 설정(기기 축)으로 갈린 것은 **코드로 덮지 말고 문서·화면 안내로 갈라라**(§7).

## 9. 체크리스트

컷·여백·템플릿·인쇄 경로를 고쳤으면:

- [ ] `cut=feed|full|partial` 각각 **끝 바이트가 정확**하고 **컷 1회**, **컷 뒤 0바이트**
- [ ] `cut=none` 이면 컷 바이트가 **전무**(불변 조항이 의도를 덮지 않는다)
- [ ] `cut` 블록 없는 템플릿도 `feed` 에서는 컷 1회 / `none` 에서는 0회
- [ ] 옛 저장본의 `tpl.cutMode` 가 존중되고, 설정(`cfg.cut`)이 그것을 이긴다
- [ ] 순수 기본값 저장 시 저장분이 `{version:N}` 뿐(오버라이드 0)
- [ ] `width` 만 바꿔 저장하면 `blocks` 는 저장되지 않고, 병합 결과의 blocks 는 **코드 기본값**
- [ ] v2 통째 저장본은 내용 존중 + 버전 상향 + cut 블록 주입
- [ ] 모든 인쇄 경로가 `printReceipt` 를 지나고 로그에 `source` 가 남는다(발권·재인쇄·회수·브리지·테스트)
- [ ] 편집기에서 설정 변경이 **즉시 저장**되고, 로그에 그 값이 그대로 나타난다
- [ ] 편집기 768×1024 세로에서 가로 스크롤 없음, 버튼 글자 줄바꿈 없음, 콘솔 오류 0

검증 스크립트: 바이트 계약은 node 로 순수 검증 가능(`buildEscpos` 는 DOM 무의존 폴백 경로를 갖는다).
